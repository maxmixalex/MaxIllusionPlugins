# 业务插件 UI 复刻核对

## 基准与边界

本次以 `c0380d6` 为迁移前基准。它是 `463915d` 将四个业务插件接入 MaximumUI 之前的版本。核对对象是实际窗口实现、控件排列及其业务回调，不以此前文档中“流程未改变”的描述代替核对。之前的迁移确实引入了分页、主从式编辑、额外选择步骤、不同的按钮文案和被移除的操作，以下逐项恢复。

| 插件 | 迁移前实现 | 当前实现 |
| --- | --- | --- |
| AccessoryBatchManager | [`AccessoryBatchManagerPlugin.cs`](https://github.com/maxmixalex/MaxIllusionPlugins/blob/c0380d6/src/AccessoryBatchManager/AccessoryBatchManagerPlugin.cs) 的 `DrawBatch`、`DrawWithinCoordinate`、`DrawSettings` | `AccessoryEditorView.cs`，原 `AccessoryMaximumUi.cs` 业务适配器 |
| ClothingCompression | [`CompressionGui.cs`](https://github.com/maxmixalex/MaxIllusionPlugins/blob/c0380d6/src/ClothingCompression/CompressionGui.cs) 的 `DrawList`、`DrawEditor`、`DrawCoordinateImport` | `CompressionEditorView.cs`，原 `CompressionGui.cs` 和 `CompressionEditorData.cs` 缓存适配器 |
| ExpressionControl | [`ExpressionControl.cs`](https://github.com/maxmixalex/MaxIllusionPlugins/blob/c0380d6/src/ExpressionControl/ExpressionControl.cs) 的 `GUIFunc`、`GUIFuncProgram`、`AddUnitPanel`、保存窗口 | `ExpressionEditorView.cs`、`ExpressionProgramWidgets.cs`、`ExpressionMaximumUI.cs`，实际 `ExpressionEditorOperations.cs` 回调 |
| JuiceControl | [`JuiceControl.cs`](https://github.com/maxmixalex/MaxIllusionPlugins/blob/c0380d6/src/JuiceControl/JuiceControl.cs) 的窗口与保存对话框 | `JuiceEditorView.cs`，`JuiceMaximumUi.cs` 业务适配器 |

保留 MaximumUI 的亮色 MDL2 绘制、可调整大小窗口、滚动和虚拟化。恢复控件的分组、相对位置、文字、动作和选择语义；方向按钮使用一致的几何图形。原界面的固定像素尺寸不作为字形、触达区域和小窗口可用性的限制。XML 原子保存、损坏文件保护、目标身份检查、独立对象复制、运行时兼容等修复继续保留。

## ExpressionControl

### 窗口结构

原来是两个可以同时显示的窗口。之前迁移将其变成四个页面，并把可直接编辑的程序单元列表改为必须先选中的主从式编辑器；这改变了操作路径。

本次恢复：

- 主窗口为单列，表情、表情预设、场景预设、运行中程序同时存在。
- `编辑表情程序` 显示/隐藏独立程序窗口，主窗口继续显示。
- 全局快捷键隐藏界面时保留程序窗口打开状态，再显示时一起恢复；场景生命周期关闭时清理两窗。
- 主窗与程序窗分别挂载，回调使相关窗口失效重建；没有新增业务页签、搜索步骤或设置页。
- 点击可交互窗口或调用 `MaximumUIRuntime.Focus` 会将它移到同一窗口层的最前方，恢复两窗重叠时的选择行为；模态对话框仍优先，窗口不会越过显式的非窗口覆盖层。隐藏窗口会丢弃尚未提交的输入草稿，重新打开时不会提交上一次会话的旧值。

### 程序窗口控件清单

顶部为程序前一个/下拉框/后一个、`新建保存`、`覆盖保存`、`删除`。右侧表达式列表顶部为 `表情排序`。

左侧滚动区域的每个单元直接呈现全部条件，每个单元均有选择控件和上移/下移方向按钮；当前选中单元保留整块面板的强调色边框。按原列顺序排列：

| 列 | 原字段 |
| --- | --- |
| 动作 | `爱抚`、`侍奉`、`插入`、`口交`、`自慰`、`百合` |
| 状态 1 | `待机`、`接吻`、`弱循环`、`强循环` |
| 状态 2 | `男冲刺`、`女冲刺`、`男绝顶`、`女绝顶` |
| 状态 3 | `男绝顶后`、`女绝顶后`、`精饮待机` |
| 数值范围 | `敏感度:` 两个文本框；`绝顶次数:` 两个文本框；Enter 或失焦提交，保持上下限约束 |
| 控制部分 1 | `形态`、`泪`、`脸红`、`高光` |
| 控制部分 2 | `瞳孔Y`、`缩瞳` |

右侧仍为当前选中单元的表达式复选框列表。点击 `表情排序` 切换为每项上移/下移按钮，再次点击退出排序并按原逻辑保存已修改顺序。左侧单元以及右侧表达式列表均虚拟化；无需把所有单元预先构建为控件。

底部保留上移/下移、`添加`、`复制`、`复制到下方`、`删除`。程序选项仍为两行：第一行 `应用嘴巴开合`、`口交时不应用口型`，第二行 `接吻时禁用程序`。

保存提示恢复 `请输入表情名`、`请输入程序名`、`请输入场景预设名`；覆盖为 `要覆盖（并重命名）吗？`。删除提示 `确定要删除吗？` 后显示名称。保存和删除对话框按钮均为原顺序 `确定`、`取消`。

### 行为与性能保护

- 实际表情/程序下拉框直接保留 XML 列表身份，20,000 个表情预设不随滑块拖动复制或筛选整个集合。
- 保存后、重排后和 XML 重载后，两个窗口使用同一最新预设集合；程序编辑仍深复制保存对象。
- 单元使用稳定对象身份生成字段键。移动单元不会把正在编辑的数字框状态串到另一单元；删除单元或切换程序后，旧字段回调不再修改已离开的对象。
- 旧工具栏回调不能在选中单元改变后删除、复制或移动新选择；表达式复选框保持捕获的单元身份。
- 保存/覆盖对话框在角色、程序或目标表达式身份已改变时拒绝写入；XML 载入失败后，已打开的保存对话框也拒绝提交。
- 实际 XML 保存、取消不写入、删除引用清理、场景角色映射和计时恢复均使用生产方法验证。
