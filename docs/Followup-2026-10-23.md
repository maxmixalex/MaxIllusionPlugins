## 用户反馈的三个插件问题

### JuiceControl：合法空模型被误报为 InvalidDataException

已复现的原因是合法的 `xsi:nil="true"` 根节点：`XmlSerializer` 正常返回 null，但首轮修复把 null 直接视为损坏文件。这是兼容回归。现在 JuiceControl、ExpressionControl 都把它规范化为空模型；读取本身不会改写磁盘。ClothingCompression 已有对应兼容路径。扫描没有发现 AccessoryBatchManager 或 MultiTeamH 另有同类预设 XML 反序列化入口。

同时修复两项实际问题：

- Common 在反序列化成功后继续读到 EOF，防止根节点后的注释掩盖第二个根或尾随垃圾；不能只凭 Deserialize 返回就允许覆盖文件。
- ExpressionControl 载入失败后保留有效内存并阻止保存，成功重载才恢复写入。JuiceControl 的错误面板持续显示真实文件路径、最内层错误与重载提示，普通状态消息不会抹掉故障；完整异常保留在日志中。

测试覆盖 UTF-8 有/无 BOM、UTF-16 LE/BE、Unicode 路径、合法空根/nil 根/尾随注释，以及空文件、截断、非法字符、错误根节点、DTD、非法数值和根后的额外内容。无效文件的原始字节、最后有效内存与保存阻止状态都有断言。

**尚未获得用户实际报错的 XML 文件和完整异常堆栈。**因此已经证明并修复一种明确的 InvalidDataException 来源，并增强其它错误的定位与保护；不能断言该根节点就是用户文件的唯一原因。

实现：[AtomicXmlFile](../src/Common/AtomicXmlFile.cs)、[XmlFileDiagnostics](../src/Common/XmlFileDiagnostics.cs)、[PresetStore](../src/JuiceControl/PresetStore.cs)、[XmlMgr](../src/ExpressionControl/XmlMgr.cs)。

### ExpressionControl：L 键与多队上下文

原逻辑在 LateUpdate 中创建 GUIMgr，其中具名 GUIStyle 需要有效的 IMGUI skin。现在 LateUpdate 只排队窗口切换；创建和绘制均在 OnGUI 内完成，一次按键只切换一次，并在异常路径恢复共享 GUI 状态。开窗请求先于表情处理记录，后续 Proc 出错不会丢失该请求。

多队兼容层先恢复完整角色列表来保留已有 FemaleData，再在刷新后重新筛选执行中的队伍。表情锁和程序不因另一队刷新而消失。H 状态优先使用当前队伍的 HFlag；缺少动画数据可恢复，同名动作状态下的动作切换也会更新。

新增 10 项实际方法回归在旧版上为 **2 通过 / 8 失败**，修复后全部通过；兼容层另有角色刷新与异常恢复测试。外部 Unity/游戏边界使用明确替身，未在 Koikatsu 中执行按键与表情动画。

实现：[ExpressionWindowLifecycle](../src/ExpressionControl/ExpressionWindowLifecycle.cs)、[ExpressionHSceneState](../src/ExpressionControl/ExpressionHSceneState.cs)、[ExpressionControlCompat](../src/MultiTeamH/ExpressionControlCompat.cs)。

### MultiTeamH：非焦点队伍自动结束

在减号面板新增“非焦点队伍侍奉 / 插入满槽自动高潮”，默认关闭，持久化为 `Background teams / Automatic climax`。可选择外部或内部结束，默认外部；侍奉动作不支持内部或原生界面要求仅外部时，回退到可用的外部结束。

开启后，仅在后台队伍男性槽达到 100、真实 Animator 与逻辑循环一致且没有过渡时提交原生 inside/outside 点击请求。侍奉限定 OLoop；插入限定普通及后庭的慢/快循环。锁槽、语音等待、待执行动作、已有 finish、动作选择、场景结束及原生 UI 尚不可交互时不提交。

注入点在后台队伍上下文恢复后、该队原生 Update 前。代码只提交游戏自身的请求和语音等待状态；动作、声音、统计与恢复继续由原生流程处理。已核对用户提供的 HSprite、HHoushi、HSonyu、SetPlay 和 IsSpriteAciotn 实现。女性满槽的既有原生规则保留。

实现：[BackgroundClimax](../src/MultiTeamH/BackgroundClimax.cs)、[调用位置](../src/MultiTeamH/TeamSession.cs)；范围和用户入口见 [MultiTeamH README](../src/MultiTeamH/README.md)。

## MaximumUI 0.2.0

### 外观与独立 Gallery

按最接近用户“Metra”描述的 [Metro for Steam 重制项目](https://github.com/RoseTheFlower/MetroSteam) 公开预览与配置取向设计：分层不透明表面、独立标题条、方正边缘、蓝色强调、稳定的选中标记和明确的正文/标题/次要文字。未复制第三方图像或皮肤代码。

- 默认 Metro Dark，提供 Metro Light，保留 Clean Light / Expression Light。
- Label 的 Body / Heading / Muted 角色和 Button 的 Default / Primary / Quiet / Danger 语义实际进入原生样式与测量。
- 补齐原生 Panel、TableCell 和显式表头背景，修复 Gallery 表格固定高度小于真实内容的问题。
- 完整主题滚动条共享一个按需创建的私有 GUISkin；自定义主题拥有并释放自己的纹理和 skin。主题切换调用 `MaximumUIRuntime.SetTheme`，统一更新布局、绘制和对话框上下文。
- Gallery 包含 Overview、Controls、Composition、Dialogs、Appearance、Large lists、Diagnostics 七页，默认 940×720，可缩放；仅构建当前页。大列表包含 10,000 行，数据只生成一次，查询改变时才过滤。
- ThemeEditor 增加可选 token 列表，颜色使用真实 RGBA 编辑。Gallery 仅显示原生后端实际支持的项；原生 Metro 的 Radius、BorderWidth、自定义禁用文字/背景 token 尚不生效，不再显示为可应用设置。通用 ThemeTokens / WidgetPainter API 保留这些字段。

### 输入、窗口、浮层和生命周期

- 在绘制前确定鼠标/键盘所属挂载，处理覆盖关系、拖动捕获、鼠标松开、隐藏、卸载与模态优先级；底层 Query 不再报告穿透点击。
- 维护与旧 Unity 滚动/分组相同的屏幕坐标和祖先裁剪交集。下拉、菜单、提示、拖放与 Query 使用正确坐标；滚出视口的自绘控件不能捕获点击，输入登记也裁掉不可见部分。
- 窗口拖动、右下角缩放、折叠恢复与小屏幕边界处理。释放事件即使已被其它 OnGUI 消费，也会在 finally 清除本 renderer 的捕获和拖放 payload。
- Tab / Shift+Tab、常用控件 Enter / Space、列表和下拉方向键/Home/End/Page、滑条方向键与 Shift 快调、树节点方向键均尊重键盘归属；没有键盘归属的界面不会自动激活控件。
- RequestFocus 按逻辑控件 ID 的新请求处理，保留界面重绘不会重复抢焦点；FocusPath 正确解析带 key 控件。旧版的三个对应反例均失败，修复后通过。
- 下拉以当前值打开，只处理可见行。菜单避免点击透传，支持嵌套菜单与返回；Tab/Escape 优先交给浮层。标签页拖动在按钮消费 MouseUp 后仍能完成一次重排。
- InputInt / InputFloat / InputDouble 支持实际键入、保留中间态、实时有效值、Enter/失焦提交和 Escape 回滚。识别延迟回调确认；文化相关的小数、范围、NaN/Infinity/溢出都经过校验。输入器只接收 round-trip 数值文本，美化格式单独绘制，避免首次聚焦把长 double 截断并改值；转只读不提交未完成缓冲。
- 对话框测量与排列使用真实 DialogPadding。Alert/Confirm 按实际字体测量消息和按钮区域；长消息只滚动正文，按钮留在可见区域。
- 挂载 Update 使用稳定快照；回调中卸载/新增不会破坏遍历。卸载幂等并清理资源，排队操作绑定来源挂载，已经卸载的视图不会继续执行自己的操作。

### 性能证据

以下均来自真实生产类在 .NET 9 宿主的测试，不包括原生 Unity 渲染与游戏负载。

| 场景 | 执行断言 / 测量 |
| --- | --- |
| 10,000 个选项，静止 300 次 GUI 更新 | 枚举一次、格式化 10,000 次；相同过滤复用结果，改变过滤不重新格式化 |
| 100,000 行虚拟列表，同一视口 300 次 | 只构建并测量 13 行（可见行和 overscan）；缓存保留 13 行 |
| 虚拟列表逐行滚动 | 每次仅构建进入视口的一行，移出的缓存删除；宽度改变重新测量，位置改变仅重新排列 |
| 输入路由与 Query，预热后 10,000 次 | 0 字节托管分配 |
| 坐标栈，预热后 640,000 次 push/pop | 0 字节托管分配，包含剪裁、命中与滚动条视口计算 |
| 数值输入空闲 Synchronize，10,000 次 | 0 字节托管分配 |

构建/布局微基准在同一个修复后程序集上运行：1,000 个 Label、150 帧、每帧两个 GUI 事件。

| 策略 | 建树 / 布局 | 托管分配 | 本次耗时 |
| --- | --- | --- | --- |
| 逐事件 | 300 / 300 | 129,062,440 B | 175.221 ms |
| 默认逐帧 | 150 / 150 | 64,538,576 B | 82.695 ms |
| 按需空闲 | 1 / 1 | 430,432 B | 0.284 ms |

这是策略对比，不是旧 DLL 与新 DLL 的端到端性能比较。不能据此声称整体 OnGUI 零分配或游戏帧率提升某个倍数。普通 ScrollView 仍遍历其完整控件树；大量数据应使用 VirtualList。缓存失效约定见 [库 README](../src/MaximumUI/README.md)。

1. Gallery：深浅主题、真实中日文字体、大小字体、窗口缩放和折叠、多级滚动、下拉/菜单边界、重叠窗口、拖动释放、Tab/键盘、数值粘贴、模态对话框和长期内存/帧耗时。

3. ExpressionControl：进入 H 后按 L、反复切队及刷新人物，确认表情锁和程序不会跨队丢失。

MaximumUI 的下一步接入应在这些原生交互和视觉验收后决定；本次没有改变功能插件的现有 UI。
