## 设计依据与实现选择

主要依据是 Microsoft 2015 年的 [UWP app design guidelines v1509](https://download.microsoft.com/download/2/4/A/24A81A29-77CF-4AA5-967E-64E42554F21B/UWP%20app%20design%20guidelines%20v1509.pdf)，其中第 303 页列出了 Windows 10 的字体阶梯。使用这一时期的规范，避免把现行 Windows 11 控件外观当成 MDL2。另参照 Microsoft 2015 年 [Responsive Design for Universal Windows Apps](https://learn.microsoft.com/en-us/archive/msdn-magazine/2015/windows-10-special-issue/ui-design-responsive-design-for-universal-windows-apps) 对 Segoe 排版、设备密度和 4 × 4 有效像素网格的说明。

| 项目 | 本轮实现 | 取舍 |
| --- | --- | --- |
| 默认主题 | `MetroLight`，白色窗口、中性灰表面、蓝色强调 | 主题缺省值和 Gallery 首次打开均为亮色，仍保留深色主题 |
| 正文 | 14 px / 20 px | 2015 UWP 的 Body 是 15 / 20；本库为鼠标键盘桌面工具采用稍紧凑的 14 / 20 |
| 页面标题 | 24 px / 28 px，Semilight | 每页一个标题，去除重复品牌标题、宣传副标题和徽标 |
| 分区标题 | 20 px / 24 px | 以文字层级分组，避免给每组再加卡片或外框 |
| 辅助文字 | 12 px / 16 px | 原规范 Caption 为 12 / 14；采用 16 px 行高以贴合 4 px 网格 |
| 布局 | 主要使用 4、8、12、16、24 px 间距 | 普通控件从 32 px 行高开始，必要的行高与宽度随字号增长 |
| 形状 | 方形输入和按钮、平面表面、克制边框 | 开关保留其表达开/关的圆轨道与圆形滑块；不将圆角套在所有容器上 |
| 反馈 | 独立悬停、按下、焦点、禁用和选中状态 | 键盘焦点通过描边表达；输入边框与表面分离，避免只靠颜色轻微改变 |
| 图标 | 共用 `Mdl2IconGeometry` 的线条与几何图元 | 搜索、方向、关闭、加减、勾选等不依赖普通 Unicode 字符的字体外观 |

Microsoft 的 [Segoe MDL2 Assets 说明](https://learn.microsoft.com/en-us/windows/apps/design/iconography/segoe-ui-symbol-font) 明确指出：这些图标属于字体私用区，只有能显式选择对应字体时才应直接使用字形。本库运行于旧版 Unity，并有 Linux 模拟渲染，因此采用统一几何图标，避免图标落入字体回退后变成字母、缺字或风格不一致的符号。

排版与颜色实现集中在 [ThemeTypography](../src/MaximumUI/ThemeTypography.cs)、[ThemeFonts](../src/MaximumUI/ThemeFonts.cs)、[ThemePalettes](../src/MaximumUI/ThemePalettes.cs) 和 [MaximumTheme](../src/MaximumUI/MaximumTheme.cs)。这些选择是对游戏内桌面工具的具体适配，不声称是 UWP 原生控件或每个像素都等同 Windows 系统窗口。

## 完整模拟渲染的路径

[MaximumUI.Preview](../tests/MaximumUI.Preview/README.md) 加载本次编译的 Gallery 程序集，执行生产 `GalleryScenes.Create → GalleryView.Build → LayoutEngine → WidgetPainter`，再将生产 DrawList 导出为 SVG，由 Inkscape 栅格化为 PNG。

其中的屏幕尺寸和字体度量有明确的托管替代边界；普通和虚拟滚动使用生产几何及行构建器。弹层复用生产的选择缓存、布局与绘制 helper。HTML 页面只选择已经导出的画面，不实现另一套表单或控件，也没有通过图片生成工具绘制示意稿。

完整导出为 **234 帧**，包括 227 张 Gallery 帧和 7 张业务编辑器帧。严格文字检查的最终结论见开头验证结果。

### 字体与文字检查

Windows 原生路径按字重选择 Segoe UI 字体，并包含中文和日文字体回退。Linux 导出使用 Pango 对 SVG 相同的字体链进行排版；字体链记录为 `Segoe UI, Selawik, Noto Sans, DejaVu Sans, Noto Sans CJK SC, Microsoft YaHei`。本次 `preview-manifest.json` 的 `primaryFont` 实际解析为 **Selawik**，并非 Segoe UI；这项记录避免把首选字体名称误当成实际运行的字体。

检查发现，CJK 字体优先时，拉丁文字基线和墨线范围与目标字体明显不同。因此明确采用拉丁字体优先、CJK 按字符回退的字体链，并记录实际解析结果；没有通过移动文本坐标、放宽阈值或取消内容框裁切来隐藏问题。较宽的真实回退字体进一步暴露了固定按钮宽度不足，随后按字号扩大实际控件。

实际字形检查还发现，Pango 的整像素 advance 与 Inkscape 的连续矢量字形度量存在差异，且 Inkscape 不接受 SVG 中的 `font-weight="350"`。导出器因此统一字体测量设置与兼容字重映射，再用原有内容框和检查阈值复验。字形后端一致后仍超出内容框的大字标题按真实布局缺陷处理，不能归入测量误差或通过放宽阈值忽略。

文字检查既使用 Pango 度量，也查询 Inkscape 实际字形边界，与生产内容框比较。它区分正常的滚动/输入内容裁切与非预期溢出，检查水平溢出、垂直截断、同层文字重叠和缺字。弹层与背景分别处理，避免把遮盖关系错判成文字冲突。

## 性能与业务范围

Gallery 使用 `BuildEveryFrame = false`；状态未变化时复用声明树，只构建当前活动页面。Diagnostics 是有意更新的例外，每 0.25 秒标记一次刷新。10,000 个样例名称按需创建，筛选仅在查询变化时重新计算；虚拟列表只构造可见行和缓冲行。

完整清单中的 Large lists 默认场景显示：同样 10,000 个数据项，标准窗口构造 18 行、最小窗口 13 行、大字窗口 16 行。这是对行虚拟化的具体证据，不是游戏 FPS 或 GPU 成本测量。字体按字重缓存，主题样式和原生资源在主题创建时准备；外观编辑先修改令牌副本，Apply 才创建原生主题，替换/卸载会释放自有主题。

浮层所属控件的分配断言使用与生产渲染器相同的复用 `List<Widget>` 输入，先完整执行 10,000 次工作负载，再连续测量三个各 10,000 次的批次；每批都必须保持合法状态、稳定代次与 **0 B** 分配，不取多批最小值，也不容许非零预算。旧数组输入的测试曾在一个 CI 冷进程记录 12,336 B，本地独立进程和分操作探针未复现该数值，来源尚未完全定位。因此验证结论限于完整预热后的稳定路径，不宣称 CoreCLR 冷初始化或整个 OnGUI 零分配。

完整托管回归同时执行固定工作负载：1,000 个 Label、150 帧、每帧两个 GUI 事件，统计 Build/Layout 的次数与分配量。

| 同一引擎的重建策略 | Build / Layout | 分配字节 |
| --- | ---: | ---: |
| 每个事件重建 | 300 / 300 | 143,476,840 |
| 每帧重建 | 150 / 150 | 71,745,776 |
| 保留未变树 | 1 / 1 | 478,480 |

这项测量验证未变化的树可避免反复构建和布局。短时计时随执行环境波动，因此这里保留更直接的次数和分配量；数据用于比较同一引擎的重建策略，旧版本二进制、Unity 绘制和游戏帧率不在该测量范围内。

本轮四个业务编辑器主要继承统一亮色缺省主题和库控件样式。ExpressionControl 原先显式指定深色，改为显式亮色并同步主题状态；程序编辑器左列由 150 px 调到 164 px，以容纳已有中文命令。ClothingCompression 列表移除 Unicode 圆点状态图标：启用项不加前缀，禁用项使用“已停用”文字。未重新组织业务页签、改变业务操作回调或更换配置流程。此前已接入的 AccessoryBatchManager、JuiceControl、ExpressionControl、ClothingCompression 继续使用各自既有 View。

最后更新的 ClothingCompression PNG 已确认启用条目无圆点前缀、列表和编辑区布局正常；预览样例均为启用项，停用文字分支与生产声明直接核对，没有将它算作已渲染的额外状态。

## 实机验证边界

字体、间距、对齐、层级与一致性由生产布局、共享字体规则、实际字形边界、完整滚动覆盖和人工查看共同检查。交互覆盖包含目录状态、真实服务按钮回调、弹层采样以及键盘/弹层回归；无障碍检查限于可见焦点、禁用/选中区分、放大字号和颜色对比断言，不声称完整的系统无障碍认证。

当前没有在此环境启动 Unity、Koikatsu 或 BepInEx。模拟渲染证明的是实际控件声明、布局、绘制命令、字体回退和采样状态的行为；中文输入法、系统字体加载、窗口捕获、游戏快捷键、原生纹理以及 GPU 输出仍需实机检查。Image 没有原生纹理时保持真实空态，不能据此宣称已验证游戏中的图片内容。
