# 2026-10-23 全仓审计与修复记录

> 这是首轮审计的历史记录。后续反馈的修复、MaximumUI 0.2.0、当前版本与 226 组回归见 [后续修复记录](Followup-2026-10-23.md)。

## 范围与结论

审计基线是 `17f2d36`（Import plugin workspace and development documentation）。本轮并行检查五个功能插件、MaximumUI、独立 Gallery、Common 与构建/测试基础设施，修复能根据代码、参考实现或执行回归确认的问题。MaximumUI 仍只在 Gallery 中使用，没有接入任何功能插件。

工作分为饰品/服装、MultiTeamH、MaximumUI、ExpressionControl/JuiceControl/Common 四条并行线，集成前交叉检查错误恢复、共享状态、文件保护和测试入口。参考资料是用户单独提供的 `MultiTeamH-agent-reference-v2.zip` 中的游戏/插件 C#、IL 和程序集。该资料用于核对具体实现，没有复制到源码提交。

这是一轮有执行证据的修复，不是“已经证明所有插件没有其他问题”。本环境没有运行 Koikatsu，也没有原生 Unity 渲染环境。下文区分编译、托管回归、受控基准和待游戏内验证事项。

## 各插件的确认问题和修复

### AccessoryBatchManager

主要实现见 [AccessoryOperations](../src/AccessoryBatchManager/AccessoryOperations.cs)、[AccessoryHighlighter](../src/AccessoryBatchManager/AccessoryHighlighter.cs)、[MaterialEditorBridge](../src/AccessoryBatchManager/MaterialEditorBridge.cs)。

- 跨搭配同号槽位不再被当作原地操作跳过；服装转饰品也允许同号源/目标，因为两者属于不同集合。
- 源和目标都是同一个非当前搭配时，操作指定搭配，避免改到当前角色的饰品数组。
- 当前搭配读取 `nowCoordinate` 工作副本；非当前搭配读取存储副本。按用户提供的 `ChaControl.SetNowCoordinate` / `ChangeCoordinateType` / `AssignCoordinate` 实现核对，二者不能无条件视为同一个对象。
- 重叠移动/调整复制先快照源；不会先写一个目的槽，再把它当成尚未读取的源，或在清空源时抹掉刚写入的目的槽。
- 非当前搭配的卡片导入不再发送缺少搭配参数的当前饰品变更事件，避免 MaterialEditor 清除当前搭配属性。
- 外部卡中的 null/畸形调整数组在写入前整体验证；正常空槽仍然有效，null 目标可以初始化为普通空槽。
- 重载协程的异常与显式释放路径均进入 `finally`，恢复角色 Renderer 的原可见状态、材质快照并释放子迭代器。
- 高亮材质使用本插件自己的副本；清理时只移除自己的覆盖层，保留别的插件修改的基础材质。饰品模型换实例后也会重新附着。
- 过期的确认窗口、Maker 原生按钮安装协程、GUI 状态及卡文件检查得到相应的边界处理。

### ClothingCompression

主要实现见 [CompressionController](../src/ClothingCompression/CompressionController.cs)、[CompressionModels](../src/ClothingCompression/CompressionModels.cs)、[ItemCatalog](../src/ClothingCompression/ItemCatalog.cs)。

- 控制器记录上次载入/保存的条目 ID，删除或解绑最后一个条目后，保存能移除对应旧记录，同时保留其他角色/搭配/物品的数据。
- 同一个装备重复占槽时不再重复载入同一配置；角色配置统一在全局配置后应用，防止优先级取决于槽位顺序。
- 可见性签名在成功重建后才提交；启用开关和衣物显示变化会真正触发衣物重烘焙。
- 删除全部形变后清除已提交的签名，避免反复请求没有内容的重建。
- 同一帧共用装备快照，下帧及重载正常刷新；检查不适用骨骼、隐藏/禁用衣物的条件提前到网格克隆之前。
- 未绑定模式只预览身体，与既有 UI 描述一致。
- 损坏 XML 重载失败时保留最后有效配置和未保存编辑，禁止之后静默覆盖主文件或污染最后有效 `.bak`；修复并成功重载后才恢复保存。
- 保存复用 Common 的原子写入，保留既有 XML、角色键和 `.bak` 语义。

几何形变算法本身没有重写。网格与外部插件共同使用时的视觉效果仍需实机检查。

### ExpressionControl

主要实现见 [ExpressionRules](../src/ExpressionControl/ExpressionRules.cs)、[XmlMgr](../src/ExpressionControl/XmlMgr.cs) 与 [ExpressionControl](../src/ExpressionControl/ExpressionControl.cs)。

- 空候选单元、已删除 GUID 和 null 条目不会进入零长度随机数组；选择仍然先等概率选有效单元，再选单元中的有效表情。使用 GUID 集合避免为每个引用重复遍历全部表情。
- 补齐 `drinkVomitWait` 状态匹配，集中验证所有状态标记与身体部位筛选。
- 嘴巴开合恢复使用开合锁，避免仅锁口型时把未锁的开合值也重置。
- 删除程序后统一刷新当前程序索引和单元选择，避免从多单元程序切到少单元程序后窗口越界。
- 空白快捷键会取消原绑定，输入解析不依赖当前语言区域；零时长/相同值插值仍通知完成。
- 人物发现处理场景间不存在管理器、空列表/角色和重复条目，返回自己的列表。
- XML 构造函数不再有文件副作用；读取先规范化候选模型再发布，坏文件不会替换当前有效内存。缺失表情 ID 独立生成，既有有效 ID 和关联保持。
- 启动加载失败会记录明确错误并停用未初始化组件，原生表情 hook 放行，防止后续每帧异常或用空预设覆盖损坏文件。修复 XML 后需重新加载插件。
- 插件卸载解绑场景事件、撤销自己的 Harmony patch，GUI 结束时恢复共享颜色和 enabled 状态。

模型抽取保持原命名空间、嵌套类型、字段和 XML 名称；没有迁移用户预设格式。删除程序和锁定方法抽为 partial 文件供真实方法测试，测试宿主仅用 XML 克隆适配 .NET 9 已移除的 BinaryFormatter 运行时边界，未声称验证生产 Mono 的该序列化器。

### JuiceControl

主要实现见 [SkinEffectsBridge](../src/JuiceControl/SkinEffectsBridge.cs)、[PresetStore](../src/JuiceControl/PresetStore.cs)、[PresetModels](../src/JuiceControl/PresetModels.cs)。

- SkinEffects 缺失和 API 不兼容也缓存发现结果，避免每个 OnGUI 事件重新扫描程序集；启动阶段及显式重载可强制重新检测。
- 反射按完整调用参数类型解析重载，并验证枚举类型，避免新增重载导致 `AmbiguousMatchException`。
- 保存采用原子替换；损坏 XML 不再静默变成空数据。“打开 XML”不再先保存覆盖磁盘。
- 从成功载入 A 切换到损坏 B 后，仍可应用旧的内存预设，但所有持久化操作被禁止，避免 UI 打开 B、实际却写 A。B 修复且重载成功后恢复保存。
- 命名窗口改用原生模态窗口，并检查打开时的预设/角色仍是确认时的目标，防止覆盖操作漂移到另一条预设。
- 手工应用预设会同步现有的效果锁值，避免下一次 LateUpdate 把新预设恢复成旧值；同一帧共用人物发现结果。
- 卸载解绑配置事件，GUI 颜色/背景/启用状态在异常路径也恢复。

命名窗口原生模态行为与效果锁的完整游戏交互通过编译及调用路径审查，本轮无界面宿主没有模拟 Unity 窗口调度。

### MultiTeamH

主要实现见 [ExpressionControlCompat](../src/MultiTeamH/ExpressionControlCompat.cs)、[RuntimeModCompat](../src/MultiTeamH/RuntimeModCompat.cs)、[TeamSession](../src/MultiTeamH/TeamSession.cs) 和 [回归说明](../tests/MultiTeamH.Regression/README.md)。

- ExpressionControl、HCtrl、AutoSpeed、Cyu 的临时上下文在修改共享状态前建立恢复范围，并增加幂等 Harmony finalizer。原方法或 prefix/postfix/清理报错时，仍尝试恢复调用者队伍、角色列表、flag、镜头、UI、光标与插件状态。
- 后台表情重放不重复处理非托管角色；结束场景清除角色和兼容状态缓存。
- Cyu 切动作/结束吻只停止跟踪到的 `BeroKiss` 迭代器，不再 `StopAllCoroutines()`。参考包中的 `Cyu.Start` 只启动一次 `Waitfor` 与 `GetMouse`，原调用会永久停止这些常驻协程。
- Breastmilk 自管协程出错后退出托管并放行原生处理，避免失去 iterator 却继续拦截原生协程造成停滞；部分绑定失败和清理异常也释放引用/标记。
- HSceneOptions 重置所有场景状态，包括循环、停止语音和计时字段。
- 原生动作菜单与头像初始化添加异常恢复；Free H 控制器销毁时解绑自己加入的原生按钮和 Canvas 监听器。
- 第二队初始化、跨帧切换的异常有统一清理，失败创建通过游戏角色管理器移除；结束时释放 `IsSwitching` 并回退焦点。
- 待启动选择带 revision，旧会话结束只完成自己的请求，不清掉下一场景的新选择。
- 保留场景 hook 的及时发现，把全局 Free H 对象兜底扫描降为每秒一次。

`CoroutineGuard` 只捕获传入迭代器自身的 `MoveNext` / `Current`。两个生产调用点仅 `yield return null`，加载轮询在父迭代器内；没有宣称它能捕获 Unity 独立推进的嵌套迭代器或自定义 yield 回调。

## MaximumUI 修复与使用约定

### 性能路径

原实现默认每次 OnGUI 事件都重建 Widget 树并重新布局。现在默认每帧构建一次，同帧事件复用树和布局；显式保留逐事件兼容模式。按需视图设置 `BuildEveryOnGUI=false`、`BuildEveryFrame=false`，由 `SetState` / `MarkDirty` 驱动。

调度使用修订号，构建期间或同帧再次发生的失效不会丢失。布局缓存以根路径、控件引用与视口尺寸识别有效节点；只移动窗口时重新排列，尺寸变更重新测量。缓存最多保留 256 个根路径。

Runtime 挂载自动缓存，每次 Build 均失效。直接使用 `ImguiRenderer` 的调用者默认不缓存，以兼容直接修改控件字段的既有用法；主动开启缓存后必须在修改控件/子树/主题度量时调用 `InvalidateLayout()`。

### 外观、布局与交互

- 默认 `CleanLight` 使用浅色不透明背景、细边框、深色文字、蓝色选择态和左对齐标题，行高与字体尺寸匹配；旧 `ExpressionLight` 保留。
- 文字测量支持真实字体宽度/换行高度；修复黑色 `GUI.color` 连背景一起染黑的问题。
- 长内容 ScrollView 不再用视口高度截断内容测量，窄分栏不会因最小尺寸之和超限而溢出。
- 自定义绘制只在 Repaint 执行；拖动 MouseUp 在消费事件前保存原事件类型，正确释放控制权。
- 无 Key 窗口的下拉浮层使用真实窗口状态路径；下拉只绘制可视行。
- 多挂载的鼠标/文字/模态捕获汇总，不会被后一个挂载清空；按真实窗口状态排除折叠窗口里的声明式对话框，避免对话框未绘制却锁住输入。独立服务对话框仍然生效。
- 浮层顺序稳定，最上层对话框拥有 Escape/鼠标输入，下层下拉不能抢先消费事件；禁用/不可聚焦控件不参与键盘导航。
- 对话框确认先关闭来源，再运行回调；回调新开窗口不会被误关，`CloseAll` 不会在回调不断开新窗口时无限循环。
- `DrawList.Append(this)` 只追加调用前的命令一次；renderer、绘图资源和主题纹理按所有权释放。

Gallery 使用按需构建，仅构建当前标签页；诊断指标每 0.25 秒刷新。没有接入五个功能插件。完整 API 变化见 [MaximumUI README](../src/MaximumUI/README.md)。

普通 ScrollView 仍遍历所有子控件，大数据应使用 VirtualList。下拉开启/过滤仍需枚举选项。按需缓存不会自动监听公开可变字段；默认每帧模式仍有每帧建树成本。

## 执行验证

使用 Linux 与 .NET SDK 9.0.319。统一入口会实际运行每个控制台断言入口并检查退出码，不能用 `dotnet test` 的空发现结果替代。

```sh
dotnet restore MaxIllusionPlugins.sln
dotnet build MaxIllusionPlugins.sln -c Release --no-restore -m:1 -nodeReuse:false
python scripts/test.py --no-build --benchmark
```

四套回归合计 **136 项/组全部通过**（部分测试组包含多个子场景）：

| 套件 | 通过 / 失败 | 主要边界 |
| --- | --- | --- |
| MaximumUI.Tests（真实 net461 程序集） | 41 / 0 | 真实库的纯托管布局、状态与输入策略 |
| MultiTeamH.Regression | 29 / 0 | 真实兼容实现；外部游戏/Unity/Harmony/会话服务替身 |
| AccessoryClothing.Regression | 38 / 0 | 真实操作/控制器/材质/持久化实现；外部角色和网格替身 |
| PluginCore.Regression | 28 / 0 | 真实 XML、规则、快捷键和反射实现；外部运行环境替身 |

整仓构建结果：十三个项目全部成功，0 错误、3 警告：2 处为 ClothingCompression 原有的 `Application.loadedLevelName` 过时 API；1 处为 .NET 9 饰品/服装测试宿主链接 net35 的 `XmlReaderSettings.ProhibitDtd` API 时产生的过时提示。测试项目及可复跑基准不复制到插件汇总目录。PowerShell 入口做过代码审查，本次环境未安装 pwsh，执行使用 Python/.NET 入口。

### 修复前确实失败的对照

在隔离临时工程里，保留相同测试和边界替身，只把指定生产文件换回 `17f2d36`：原始 AccessoryOperations 有 11 条相关失败，原始 CompressionController 有 5 条相关失败。这是指定组件的反例，不是原始整仓测试总数。

后续外部卡畸形数组/损坏形变 XML 的新增用例，在改对应生产代码前为 31 通过、7 失败，修复后为 38 通过、0 失败。

装备查询同一用例中，100 次可见性检查、20 件装备，目录查询从 2,000 次降为 20 次，下一帧正常刷新。这是可观察工作量，不能解读为游戏帧率提高 100 倍。

### 独立 DLL 性能对照

实际分别构建原始 `17f2d36` 与修复后的 MaximumUI DLL，在两个独立进程中执行相同基准源码。场景为 1,000 个 Label、150 帧、每帧 2 个 GUI 事件，每种模式 3 次预热、5 次测量取中位数。

| DLL / 模式 | 建树 / 布局 | 中位耗时 | 线程分配 |
| --- | ---: | ---: | ---: |
| 原始 / 每事件 | 300 / 300 | 40.626 ms | 126,662,440 B |
| 修复 / 每事件 | 300 / 300 | 44.431 ms | 126,662,440 B |
| 修复 / 默认每帧 | 150 / 150 | 19.913 ms | 63,338,576 B |
| 修复 / 按需空闲 | 1 / 1 | 0.133 ms | 422,432 B |

默认策略将重复工作和分配约减半。按需空闲的结果来自整个区间只构建一次；它不适用于每帧数据都变化的视图。逐事件修复版没有更快，因此不把收益归因于单次布局引擎吞吐提升。

这些数字只测托管建树/布局，不包含 Unity 原生绘制、GPU、实际输入分发或游戏逻辑，不能换算游戏 FPS。不同机器/负载的耗时会变化。复跑源码与指令见 [MaximumUI.Benchmark](../tests/MaximumUI.Benchmark/README.md)。统一测试入口的 `--benchmark` 则比较同一个修复后 DLL 的策略，不会自动载入历史版本。

## 审阅覆盖说明

所有项目都参与了源码/依赖/生命周期扫描，重点路径见上述表与各测试 README。MultiTeamH 的诊断、翻译、GUI skin，饰品/服装的 UI 与几何算法，表情/皮肤的 GUI 辅助、反射与状态应用，MaximumUI 的控件、布局、状态、输入、绘制、主题、运行时和 Gallery 均纳入审阅。没有确认问题的部分保持原实现，不以改动行数作为覆盖证据。

测试直接链接生产文件，或调用真正构建的 MaximumUI 程序集；测试替身仅覆盖需要 Unity/游戏/其他插件的边界。它们不执行 Harmony 的真实 detour、Unity 的协程调度器或实际网格渲染。显式迭代器 Dispose 测试也不等于证明 Unity 的 StopCoroutine 一定按同样方式调度清理。
