# MultiTeamH

Koikatsu 自由 H 的双队实验插件。插件在原生“选择行为”中加入“多P”模式，选择 2F2M 后组成两组可独立切换控制的 1F1M 队伍。

## 使用

- 在“选择行为”中点击新增的“多P”。
- “多P”复用原生“一般”面板，并显示“队1／队2”选择条；每队分别选择一男一女，并分别保存 H 阶段及安全日／危险日。原生“复数”面板不会被修改。
- 四名角色就绪后点击原生确定按钮。
- 点击左上角头像上的“队伍 1 / 2”，或按 `Tab`：切换原生 H UI 当前控制的队伍。头像、进度条、动作菜单和移动轴随当前队伍切换。
- `-`（主键盘或小键盘减号）：显示或隐藏控制面板。
- KK_HCtrl 面板跟随当前焦点队伍显示，两队后台控制状态分别保存。
- 控制面板可分别设置两队的视线、头部是否跟随相机。
- “显示非活动队”：控制另一队是否留在场景中。
- “非焦点队伍侍奉 / 插入满槽自动高潮”：默认关闭，可在减号面板或 BepInEx 的 `Background teams / Automatic climax` 中启用。
- “自动结束方式”：可选外部（默认）或内部，保存到 `Background teams / Climax finish`。侍奉动作没有内部结束选项、或该队原生界面选择了仅外部时，会使用可用的外部结束。

两队从原生“一般”自由 H 启动。每队拥有独立的 `HFlag`、`HActionBase` 动作列表、快感、高潮、动画和坐标状态，并行执行完整 H 流程。原生 H UI 只显示并控制当前焦点队。

入口基于“一般”自由 H；动作菜单还追加了带前缀的百合、自慰和 3P 动作。多人动作会临时共用参与角色的动作上下文，切出后恢复各队状态。Darkness 不属于此插件入口。

继续开发前请阅读 [开发交接说明](../../docs/MultiTeamH-Handoff.md)，其中记录了最近验证状态和反编译参考资料的提供方式。

## 后台自动高潮的范围

0.11.64 在后台队伍男性槽达到 100 时提交一次原生结束请求，由游戏继续完成语音、动作、统计和恢复流程。焦点队伍、锁定男性槽、待执行点击、语音等待、动作切换、场景结束，以及非侍奉/插入的动作均不提交请求。插入支持普通及后庭的慢/快循环，侍奉在 `OLoop` 时触发；不自动切换姿势或强行启动暂停的动作。女性满槽时游戏本来已有的自动高潮规则仍由原生流程处理。

此版本还修复了 ExpressionControl 的角色刷新会破坏当前队伍过滤、并丢失另一队表情设置的问题。完整列表用于保留已有的 `FemaleData`，刷新结束后恢复执行队伍过滤；异常时也释放临时上下文。

无界面回归直接链接原生请求选择及兼容层生产源码，覆盖开关、焦点、锁槽、阈值、动作范围、原生请求与异常恢复。需在游戏内分别测试侍奉与插入、满槽切队、锁槽、内外结束方式及真实动作/语音，不将构建与测试宿主通过等同于游戏验证。

## 0.11.65 表情联动复查

与 ExpressionControl 0.3.1 配合，非焦点角色的原生脸部回调、眼口插值保护、程序匹配和 UI 编辑现在按所属队伍选择上下文。后台处理完成或异常后恢复调用者的动作、次数和旗标；男女角色各自只在本队处理一次。切换焦点时声音对象使用稳定的队伍身份，共享双女性动作另外使用正确的声音请求槽位。

ExpressionControl 同时修复了原生回调提前刷新状态后漏触发表情程序、相同状态换动作不重新评估、停用程序后口型忽略策略未立即释放的问题。切换选中角色、操作次数、批量应用场景预设均保留原界面操作，并使用实际目标角色上下文。

本轮 MultiTeamH 回归宿主执行 60 项，包含原自动高潮保护和新增上下文、重入、异常清理、声音身份及场景退出边界。完整实现、旧条件失败反例和实机验收范围见 [运行时审计](../../docs/Runtime-Audit-2026-10-24.md)。未在此环境运行 Koikatsu 或真实 Harmony detour，不把测试通过称为所有模组组合已验证。
