# ExpressionControl

Koikatsu 游戏与 Studio 中的表情控制插件。0.3.1 使用 MaximumUI 的亮色 MDL2 控件，恢复原主窗口和独立程序窗口，支持选择角色、编辑眉眼嘴等表情参数、保存表情预设、编辑表情程序，以及按场景保存多角色设置。

- 默认按 `L` 打开窗口；快捷键由 XML 的 `KeyConfig.showGUI` 保存。
- 表情、程序及场景预设由 `XmlMgr.cs` 管理。
- 原生表情/语音相关 hook 位于 `Hooks.cs` 和 `ExpressionControl.cs`。
- 运行依赖 BepInEx 5、KKAPI、`MaximumUI.dll` 与 `MaxIllusionPlugins.Common.dll`；主游戏和 Studio 均有对应进程入口。CI 的插件独立安装包已经带上这两个本仓共享 DLL。

```sh
dotnet build src/ExpressionControl/ExpressionControl.csproj -c Release
```

输出：`bin/Release/ExpressionControl/KK_ExpressionControl.dll`。本源码版本为 0.3.1；MultiTeamH 的历史运行测试曾使用 0.2.7.15，两者不能仅凭名称当作同一个实现。

MultiTeamH 兼容代码放在 [MultiTeamH/ExpressionControlCompat.cs](../MultiTeamH/ExpressionControlCompat.cs)。改动表情程序或持久化模型时，应保留原有 XML 数据的读取兼容性，并在游戏/Studio 中复测。

## 0.3.1 MaximumUI 双窗口

- **主窗口**：用前后方向按钮选择角色；按原顺序显示 `获取当前表情`、`固定表情`、眉/眼/嘴图案及各自前后切换、开合、瞳孔位置与大小、高光、`不眨眼`、眨眼频率/速度、泪、脸红和各项独立锁定。`不眨眼` 仍与实际 blink 状态反向绑定。
- **表情与场景预设**：在主窗口同时显示，通过两侧方向按钮或下拉框选择。表情按钮为 `新建保存`、`覆盖保存`、`删除`；场景为 `应用选中`、`新建保存`、`覆盖保存`、`删除选中`。场景按 F1/F2/M1/M2 等位置保存和恢复各角色程序与间隔。
- **当前角色程序**：继续位于主窗口底部，保留原程序选择器、倒计时、1–20 秒滑块及绝顶次数方向按钮。`编辑表情程序` 打开或关闭独立程序窗口，主窗口仍可使用。
- **程序窗口**：顶部为程序选择、`新建保存`、`覆盖保存`、`删除`，右侧为 `表情排序`。每个程序单元直接显示全部动作、状态、敏感度/次数范围及控制部分，选择单元有整块面板边框高亮；右侧保留该单元的表达式复选框列表。数值范围在 Enter 或失焦时提交。底部为上移/下移、`添加`、`复制`、`复制到下方`、`删除` 以及原三个程序选项。再次点击 `表情排序` 退出时保存已修改的顺序。

早期迁移的四页结构、角色/预设搜索、主从式程序编辑、独立设置页和主题按钮改变了原流程，0.3.1 已按 `c0380d6` 恢复。保存/覆盖/删除提示和 `确定`、`取消` 的顺序也恢复原文。完整控件清单见 [业务 UI 复刻核对](../../docs/UI-Parity-2026-10-24.md)。窗口保留 MaximumUI 的拖动、缩放、折叠、关闭和亮色主题。

保留 `L` 默认入口与 XML 中的 `KeyConfig.showGUI`。输入字段和模态对话框期间暂停窗口快捷键，防止名称中的 `L` 关闭整个编辑器；角色表情处理继续运行。首次挂载仍排队到 `OnGUI`。快捷键隐藏两窗时记住程序窗口的打开状态；场景关闭清理两窗，组件销毁时解除两个挂载。

两窗重叠时，点击其中的可交互窗口会将它移到同一窗口层的最前方；打开的模态对话框继续优先。隐藏窗口会清理尚未提交的输入草稿，重新打开不会把旧会话的值写回。

界面使用 MaximumUI 的原生声明式控件，已移除旧 `GUIMgr`、`GUIUtl` 和独立 `ComboBox`。程序单元和表达式列表按可见行创建，主窗下拉框保留实际预设列表，不在每次拖动滑块时复制或筛选全部预设。保留的控件树按修改重建；主窗口至多每 0.2 秒比较一次实时值，仅变化时请求更新，隐藏窗口不轮询界面快照。单元字段使用稳定身份，跨程序切换不复用旧输入状态；失效的单元/角色回调不会修改新选择。

XML 载入失败会显示文件路径和解析原因，停止保存，并保留上次成功读取的数据。修复文件后可按错误区域的 `修复文件后重新载入`。已打开的保存对话框同样检查读取状态；角色、程序或被覆盖表情身份变化后拒绝写入。删除表情会清除所有程序单位、编辑副本和当前角色程序中的重复引用，避免后续保存重新带回已删除 GUID；角色当前表情数值不受删除影响。

## 回归与边界

`tests/PluginCore.Regression` 直接链接实际 `ExpressionEditorView`、`ExpressionProgramWidgets`、编辑/删除/重载业务以及窗口生命周期。测试覆盖两窗的原控件和最小尺寸布局、2 万条表情的列表身份与分配工作量、角色切换后的回调目标、全部条件控件、直接编辑未选中单元、单位独立复制/移动、过期工具栏动作、命名对话框和真实 XML 保存、坏文件只读及修复重载、所有删除引用、场景角色与间隔往返。

测试使用明确的 Unity/游戏边界替身，不执行角色网格、动画或真实 IMGUI 绘制。仍需在游戏和 Studio 中验证窗口显示、中文字体、键盘/鼠标输入、表情应用与 MultiTeamH 切队行为。CI SVG 预览来自同一生产 View 配合匿名合成数据，不读取用户预设。

## 0.2.7.20 运行修复

- `L` 在 `LateUpdate` 中排队切换可见性，窗口及命名 GUIStyle 在 `OnGUI` 中首次创建。避免场景切换后没有有效 IMGUI skin 时按键无法打开窗口，反复 Layout/Repaint 也不会重复切换。
- H 状态读取优先使用兼容层提供的 `hFrag`，使后台队伍的动作、高潮次数和表情程序跟随该队，而不是共享 `HSceneProc` 的焦点队伍。
- 支持动画描述暂缺、动作名暂缺，以及循环状态名不变时切换动作，避免空引用和角色绑定不刷新。
- 与 MultiTeamH 0.11.64 一起使用时，刷新角色列表会保留两队原有的表情锁定和程序，然后只处理当前执行队伍。

这些 H 状态和分队修复保留在 0.3.1 中。`PluginCore.Regression` 继续直接链接 `ExpressionWindowLifecycle.cs` 与 `ExpressionHSceneState.cs`，检查初始化时机、窗口切换、共享 GUI 状态恢复和分队状态读取；窗口生命周期回归已升级到 MaximumUI 挂载/隐藏/卸载。

0.3.1 进一步覆盖原生表情回调提前刷新状态后的程序触发、状态枚举不变但动作已改变、定时/状态触发去重、切换程序后的嘴部策略刷新，以及所选角色动作和绝顶计数的队伍上下文。相应生产处理逻辑位于 `ExpressionProcessing.cs`、`FemaleDataRuntimeState.cs`、`ExpressionCharacterActions.cs`；MultiTeamH 的兼容层按目标角色所属队伍调用，防止非焦点角色的表情和计数串入焦点队伍。
